## 一、技术栈选型

### 1.1 前端（保留现有原型）

| 技术 | 用途 | 版本 | 理由 |
|------|------|------|------|
| React | UI 框架 | 18.x | 已有原型，无需重构 |
| Vite | 构建工具 | 5.x | 已配置，快速冷启动 |
| Tailwind CSS | 样式系统 | 3.x | 已配置，原子化CSS，深色模式友好 |
| shadcn/ui | 组件库 | 最新 | 已安装50+组件，底层工具层 |
| Framer Motion | 动画 | 11.x | 页面切换、组件动画 |
| GSAP | 复杂动画 | 3.x | 粒子背景、标题动画、Timeline |
| anime.js | 粒子驱动 | 3.x | GalaxyCanvas 粒子系统 |
| React Router | 路由 | 6.x | 已有5个页面路由 |
| lucide-react | 图标 | 最新 | 统一图标体系 |

**前端变更点：**
- 将静态 Mock 数据改为从后端 API 获取
- 新增 `api/` 目录封装 HTTP 请求
- 新增 `hooks/` 目录封装数据获取（SWR 或自定义 fetch）
- 保留所有现有页面组件和动画逻辑，只做数据层替换

### 1.2 后端（新建）

| 技术 | 用途 | 版本 | 理由 |
|------|------|------|------|
| Node.js | 运行时 | v24.x | 服务器已安装，轻量 |
| Express | Web 框架 | 4.x | 轻量、成熟、文档丰富 |
| better-sqlite3 | SQLite 驱动 | 最新 | 同步API，性能最佳，无需async/await嵌套 |
| cors | 跨域 | 最新 | 前后端分离必需 |
| morgan | 日志 | 最新 | 请求日志，便于调试 |
| dotenv | 环境变量 | 最新 | 配置管理 |

**不选 Next.js 的原因：**
- 创始人明确要求前后端分离架构
- Next.js 全栈一体化增加复杂度，不符合 MVP 轻量原则
- 前端已有 Vite 构建链，切换到 Next.js 需重构大量配置
- 部署时 Next.js 需要额外服务端配置，不如 Express 直接

### 1.3 数据库

| 技术 | 用途 | 理由 |
|------|------|------|
| SQLite | 本地文件数据库 | 轻量、零配置、单文件、备份简单 |
| better-sqlite3 | Node.js 驱动 | 同步API性能比异步高 3-5 倍，适合单机部署 |

**SQLite 适用性分析：**
- 并发量：公司内部平台，预计同时在线 ≤ 4 人，SQLite 完全胜任
- 数据量：项目 ≤ 100、任务 ≤ 1000、文档 ≤ 500，SQLite 无压力
- 备份：单文件复制即可，比 MySQL/PostgreSQL 简单得多
- 运维：零运维，无需守护进程

### 2.2 前后端分离说明

**前端（端口 3000）：**
- 提供静态 HTML/CSS/JS 文件
- React SPA，所有路由由前端处理（React Router）
- 向后端 API 发起 HTTP 请求获取数据
- 环境变量：`VITE_API_BASE_URL=http://localhost:3001`

**后端（端口 3001）：**
- Express 应用，只处理 API 请求
- 不渲染任何 HTML，只返回 JSON
- 数据库操作通过 better-sqlite3 同步执行
- 环境变量：见「部署方案」章节

### 3.2 表结构设计

#### 3.2.1 智能体表 (agents)

```sql
CREATE TABLE agents (
  id            TEXT PRIMARY KEY,           -- 唯一标识，如 'irra', 'mery'
  name          TEXT NOT NULL,                -- 显示名称
  title         TEXT NOT NULL,                -- 完整职位
  department_id TEXT NOT NULL,                -- 所属部门ID（外键）
  role          TEXT NOT NULL,                -- 角色简称
  avatar        TEXT,                         -- 头像路径
  color_theme   TEXT NOT NULL CHECK(color_theme IN ('blue','gold')),
  badge         TEXT,                         -- 徽章文字
  story_summary TEXT,                         -- 故事摘要
  story_full    TEXT,                         -- 完整故事
  abilities     TEXT,                         -- 能力标签，JSON 数组
  status        TEXT NOT NULL DEFAULT 'online' CHECK(status IN ('online','offline','busy')),
  created_at    INTEGER NOT NULL,             -- 创建时间戳（毫秒）
  updated_at    INTEGER NOT NULL              -- 更新时间戳（毫秒）
);
```

**索引：** `CREATE INDEX idx_agents_department ON agents(department_id);`

#### 3.2.2 部门表 (departments)

```sql
CREATE TABLE departments (
  id            TEXT PRIMARY KEY,           -- 唯一标识，如 'tech', 'design'
  name          TEXT NOT NULL,              -- 部门名称
  short_name    TEXT,                      -- 简称
  color         TEXT NOT NULL CHECK(color IN ('blue','gold')),
  color_hex     TEXT,                      -- 十六进制色值
  description   TEXT,                      -- 部门描述
  member_count  INTEGER NOT NULL DEFAULT 0, -- 成员数量
  head_id       TEXT,                      -- 负责人ID（外键→agents）
  created_at    INTEGER NOT NULL,
  updated_at    INTEGER NOT NULL
);
```

#### 3.2.3 项目表 (projects)

```sql
CREATE TABLE projects (
  id                  TEXT PRIMARY KEY,     -- 唯一标识，如 'p1'
  name                TEXT NOT NULL,        -- 项目名称
  description         TEXT,                  -- 项目描述
  status              TEXT NOT NULL CHECK(status IN ('in-progress','completed','planning','paused')),
  progress            INTEGER NOT NULL DEFAULT 0 CHECK(progress >= 0 AND progress <= 100),
  lead_id             TEXT,                 -- 项目负责人ID（外键→agents）
  lead_name           TEXT,                 -- 负责人名（冗余，减少JOIN）
  lead_avatar         TEXT,                 -- 负责人头像
  lead_role           TEXT,                 -- 负责人角色
  deadline            TEXT,                 -- 截止日期（如 "6月30日"）
  start_date          TEXT,                 -- 开始日期
  task_count          INTEGER NOT NULL DEFAULT 0,
  completed_tasks     INTEGER NOT NULL DEFAULT 0,
  updated_at          TEXT,                 -- 最近更新时间（如 "2小时前"）
  created_at          INTEGER NOT NULL,
  updated_at_ts       INTEGER NOT NULL      -- 更新时间戳（毫秒）
);
```

**索引：** `CREATE INDEX idx_projects_status ON projects(status);`

#### 3.2.4 项目-部门关联表 (project_departments)

项目可跨部门，多对多关系。

```sql
CREATE TABLE project_departments (
  project_id     TEXT NOT NULL,
  department_id  TEXT NOT NULL,
  PRIMARY KEY (project_id, department_id),
  FOREIGN KEY (project_id) REFERENCES projects(id) ON DELETE CASCADE,
  FOREIGN KEY (department_id) REFERENCES departments(id) ON DELETE CASCADE
);
```

#### 3.2.5 项目里程碑表 (project_cycles)

```sql
CREATE TABLE project_cycles (
  id           TEXT PRIMARY KEY,
  project_id   TEXT NOT NULL,
  name         TEXT NOT NULL,
  description  TEXT,
  start_date   TEXT,                  -- 如 "6/1"
  end_date     TEXT,                  -- 如 "6/5"
  status       TEXT NOT NULL CHECK(status IN ('completed','in-progress','pending')),
  color        TEXT,                  -- 状态色值
  "order"      INTEGER NOT NULL DEFAULT 0, -- 排序号
  created_at   INTEGER NOT NULL,
  FOREIGN KEY (project_id) REFERENCES projects(id) ON DELETE CASCADE
);
```

**索引：** `CREATE INDEX idx_cycles_project ON project_cycles(project_id);`

#### 3.2.6 协作流程节点表 (workflow_nodes)

```sql
CREATE TABLE workflow_nodes (
  id              TEXT PRIMARY KEY,
  project_id      TEXT NOT NULL,
  agent_id        TEXT NOT NULL,
  agent_name      TEXT NOT NULL,
  agent_avatar    TEXT,
  agent_role      TEXT,
  department      TEXT,
  department_color TEXT CHECK(department_color IN ('blue','gold')),
  "order"         INTEGER NOT NULL DEFAULT 0,
  responsibility  TEXT,               -- 职责描述
  created_at      INTEGER NOT NULL,
  updated_at      INTEGER NOT NULL,
  FOREIGN KEY (project_id) REFERENCES projects(id) ON DELETE CASCADE
);
```

**索引：** `CREATE INDEX idx_workflow_project ON workflow_nodes(project_id);`

#### 3.2.7 任务表 (tasks)

```sql
CREATE TABLE tasks (
  id              TEXT PRIMARY KEY,
  title           TEXT NOT NULL,
  priority        TEXT NOT NULL CHECK(priority IN ('high','medium','low')),
  status          TEXT NOT NULL CHECK(status IN ('todo','in-progress','review','completed')),
  project_id      TEXT NOT NULL,
  project_name    TEXT,                 -- 冗余，减少JOIN
  department      TEXT,                 -- 执行部门名
  department_color TEXT CHECK(department_color IN ('blue','gold')),
  type            TEXT,                 -- 任务类型
  assignee_id     TEXT,                 -- 负责人ID（外键→agents）
  assignee_name   TEXT,                 -- 冗余
  assignee_avatar TEXT,
  assignee_role   TEXT,
  due_date        TEXT,                 -- 截止日期
  completed_at    TEXT,                 -- 完成时间
  description     TEXT,                 -- 任务描述
  created_at      INTEGER NOT NULL,
  updated_at      INTEGER NOT NULL,
  FOREIGN KEY (project_id) REFERENCES projects(id) ON DELETE CASCADE
);
```

**索引：**
```sql
CREATE INDEX idx_tasks_project ON tasks(project_id);
CREATE INDEX idx_tasks_status ON tasks(status);
CREATE INDEX idx_tasks_priority ON tasks(priority);
CREATE INDEX idx_tasks_assignee ON tasks(assignee_id);
```

#### 3.2.8 文档表 (documents)

```sql
CREATE TABLE documents (
  id              TEXT PRIMARY KEY,
  name            TEXT NOT NULL,
  type            TEXT NOT NULL CHECK(type IN ('technical','design','product','meeting','architecture')),
  department      TEXT,                 -- 所属部门名
  department_color TEXT CHECK(department_color IN ('blue','gold')),
  updated_by_id   TEXT,                 -- 更新者ID
  updated_by_name TEXT,                 -- 冗余
  updated_by_avatar TEXT,
  updated_at      TEXT,                 -- 如 "2小时前"
  updated_at_ts   INTEGER,             -- 时间戳
  status          TEXT NOT NULL CHECK(status IN ('latest','update-needed','draft')),
  content         TEXT,                 -- 文档内容（扩展用）
  created_at      INTEGER NOT NULL,
  updated_at_meta INTEGER NOT NULL
);
```

**索引：** `CREATE INDEX idx_docs_type ON documents(type);`

#### 3.2.9 动态记录表 (activities)

```sql
CREATE TABLE activities (
  id           TEXT PRIMARY KEY,
  user_id      TEXT,                    -- 操作用户ID
  user_name    TEXT NOT NULL,           -- 用户名（冗余）
  user_avatar  TEXT,
  action       TEXT NOT NULL,           -- 操作动词
  target       TEXT NOT NULL,           -- 操作对象
  target_id    TEXT,                    -- 操作对象ID（扩展）
  target_type  TEXT,                    -- 对象类型（project/task/document）
  timestamp    TEXT,                    -- 显示时间（如 "09:30"）
  color        TEXT CHECK(color IN ('blue','gold')),
  created_at   INTEGER NOT NULL
);
```

### 3.3 数据冗余设计说明

**为什么使用冗余字段？**
- 项目表中的 `lead_name`, `lead_avatar`, `lead_role`
- 任务表中的 `project_name`, `assignee_name`, `assignee_avatar`
- 文档表中的 `updated_by_name`, `updated_by_avatar`

**原因：**
1. 前端需要频繁显示这些关联信息（如任务卡片显示负责人头像）
2. 避免每个列表查询都做多表 JOIN（SQLite 中 JOIN 性能不差但代码更复杂）
3. MVP 阶段数据量小，维护冗余字段的成本极低
4. 当关联对象信息变更时，通过触发器或代码级联更新

### 3.4 预留扩展字段

每个表都包含 `created_at` 和 `updated_at`，为未来功能扩展预留：
- 按时间排序、筛选
- 数据迁移时的时间戳参考
- 审计日志基础

## 四、API 接口定义

### 4.1 部门与智能体

#### GET /api/departments
获取所有部门（含智能体和负责项目）。

**响应：**
```json
{
  "success": true,
  "data": [
    {
      "id": "tech",
      "name": "技术部",
      "shortName": "技术",
      "color": "blue",
      "colorHex": "#0A84FF",
      "description": "负责公司技术架构、产品开发、系统维护",
      "memberCount": 3,
      "head": { /* Agent 对象 */ },
      "projects": [ /* 项目列表 */ ]
    }
  ]
}
```

#### GET /api/agents
获取所有智能体。

#### GET /api/agents/:id
获取单个智能体详情。

### 4.2 项目

#### GET /api/projects
获取项目列表（支持筛选和搜索）。

**查询参数：**
- `status` — 状态过滤：in-progress | completed | planning | paused | all（默认）
- `search` — 关键词搜索（匹配名称）
- `department` — 按部门过滤

**响应：** 项目数组（含 cycles、workflow 内嵌）

#### GET /api/projects/:id
获取单个项目详情（含 cycles、workflow）。

#### POST /api/projects
创建新项目。

**请求体：**
```json
{
  "name": "新项目",
  "description": "...",
  "status": "planning",
  "involvedDepartments": ["技术部", "设计部"],
  "deadline": "7月30日",
  "startDate": "6月15日"
}
```

#### PUT /api/projects/:id
更新项目信息。

#### DELETE /api/projects/:id
删除项目（级联删除关联 cycles、workflow、tasks）。

### 4.3 项目里程碑

#### GET /api/projects/:id/cycles
获取项目里程碑列表。

#### POST /api/projects/:id/cycles
添加里程碑。

#### PUT /api/projects/:id/cycles/:cycleId
更新里程碑。

#### DELETE /api/projects/:id/cycles/:cycleId
删除里程碑。

### 4.4 协作流程

#### GET /api/projects/:id/workflow
获取项目协作流程节点。

#### PUT /api/projects/:id/workflow/reorder
重新排序协作流程节点。

**请求体：**
```json
{
  "nodeIds": ["w1-1", "w1-3", "w1-2", "w1-4"]
}
```

#### POST /api/projects/:id/workflow
添加协作节点。

#### DELETE /api/projects/:id/workflow/:nodeId
删除协作节点。

#### PUT /api/projects/:id/workflow/:nodeId
更新节点职责描述。

### 4.5 任务

#### GET /api/tasks
获取任务列表。

**查询参数：**
- `projectId` — 按项目过滤
- `status` — 按状态过滤
- `priority` — 按优先级过滤
- `department` — 按部门过滤
- `assignee` — 按负责人过滤
- `search` — 关键词搜索

#### GET /api/tasks/:id
获取单个任务详情。

#### POST /api/tasks
创建任务。

**请求体：**
```json
{
  "title": "任务标题",
  "priority": "high",
  "status": "todo",
  "projectId": "p1",
  "department": "技术部",
  "type": "开发",
  "assigneeId": "irra",
  "dueDate": "6月15日",
  "description": "任务描述"
}
```

#### PUT /api/tasks/:id
更新任务（状态、优先级、负责人等）。

#### PATCH /api/tasks/:id/status
仅更新任务状态（用于看板拖拽）。

#### DELETE /api/tasks/:id
删除任务。

### 4.6 文档

#### GET /api/documents

**查询参数：**
- `type` — 按类型过滤
- `status` — 按状态过滤

### 4.7 动态记录

#### GET /api/activities
获取动态记录列表。

**查询参数：**
- `limit` — 返回条数（默认 10）
- `since` — 起始时间戳

#### POST /api/activities
创建动态记录（内部调用，记录用户操作）。

### 4.8 总览聚合

#### GET /api/dashboard
获取总览页面所有聚合数据（一次请求返回全部）。

**响应：**
```json
{
  "success": true,
  "data": {
    "kpi": {
      "totalProjects": 5,
      "inProgress": 3,
      "completed": 1,
      "pending": 1,
      "totalTasks": 26,
      "completedTasks": 8,
      "inProgressTasks": 6,
      "pendingTasks": 12
    },
    "departments": [ /* 部门数组 */ ],
    "projects": [ /* 非已完成项目前3个 */ ],
    "tasks": [ /* 活跃任务前5个 */ ],
    "activities": [ /* 最近6条动态 */ ]
  }
}
```

**设计理由：** 总览页面需要大量数据，一次聚合请求减少前端 5+ 次请求，提升首屏加载速度。

## 六、风险分析

### 6.1 高风险

| 风险 | 描述 | 影响 | 缓解措施 |
|------|------|------|---------|
| **R1：数据迁移** | 现有 Mock 数据为静态对象，需要完整映射到数据库Schema | 种子数据遗漏会导致前端展示异常 | 1. 先写完整 seed 脚本覆盖所有Mock数据；2. 开发时同时使用 Mock 和 API 双模式验证 |
| **R2：动画兼容性** | 前端大量 GSAP/Framer Motion 动画，替换数据源时可能触发时机问题 | 动画卡顿或数据未加载时动画已触发 | 1. 添加数据加载状态（骨架屏）；2. 动画在数据加载完成后再触发；3. 使用 useEffect 依赖数据就绪 |

### 6.2 中风险

| 风险 | 描述 | 影响 | 缓解措施 |
|------|------|------|---------|
| **R3：协作流程持久化** | 当前拖拽排序仅在内存，后端需持久化 order 字段 | 拖拽后刷新重置 | 1. PUT /workflow/reorder 更新 order 字段；2. 查询时按 order 排序返回 |
| **R4：看板状态切换** | 任务看板中拖拽跨列切换状态，需同步后端 | 状态不同步 | 1. PATCH /tasks/:id/status 专门接口；2. 前端乐观更新 + 失败回滚 |
| **R5：实时性** | 多人同时操作可能导致数据不一致 | 数据覆盖 | 1. SQLite 的 WAL 模式保证读写并发；2. 乐观锁（version 字段）或简单 last-write-wins |

### 6.3 低风险

| 风险 | 描述 | 影响 | 缓解措施 |
|------|------|------|---------|
| **R6：前端包体积** | 增加 axios 等依赖后 bundle 增大 | 首屏加载略增 | 1. 使用原生 fetch（无需 axios）；2. 代码分割（Vite 自动处理） |
| **R7：Cloudflare Tunnel 稳定性** | 隧道偶尔中断 | 短暂不可访问 | 1. 配置 systemd 服务自动重启；2. 监控脚本检测隧道状态 |
| **R8：备份** | 单文件数据库需定期备份 | 数据丢失 | 1. 每日 cron 复制 .db 文件到备份目录；2. 保留最近7个备份 |
