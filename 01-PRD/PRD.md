**版本：** v1.0 MVP
**日期：** 2026-06-11
**撰写人：** Mery（CIO）
**状态：** 原型完成，PRD定稿

---

## 一、产品定位

> **一句话描述：** 启明科技内部一站式管理驾驶舱，为管理层、部门负责人和 AI 智能体提供项目跟踪、任务管理、文档协作与组织架构可视化的统一平台。

### 为什么做这个平台？

启明科技目前有 2 个部门（技术部、设计部）、3 个智能体成员（JiaWen、Wenner、Irra、Mery），正在并行推进 5 个项目。项目信息散落在聊天记录、任务列表和文档中，缺乏一个统一视图。这个平台的核心目标是：

1. **降低信息不对称** — CEO 一眼看清所有项目进度
2. **强化跨部门协作** — 项目可跨部门、任务可关联项目
3. **沉淀知识资产** — 文档中心统一管理技术文档、设计稿、会议记录
4. **可视化智能体角色** — 每个智能体有独立档案和能力标签，方便新人快速了解

## 四、用户故事

### P0-01 管理驾驶舱

> **As a** JiaWen（创始人），
> **I want** 打开总览页面就能一眼看到所有项目进度、任务完成情况和最近动态，
> **So that** 我不需要逐个点开项目，就能快速判断是否需要介入。

**验收标准：**
- Given 用户打开总览页面，When 页面加载完成，Then 显示 4 个 KPI 卡片（项目总数、进行中、已完成、待处理）
- Given 用户浏览总览页面，When 滚动到部门区域，Then 显示每个部门的成员数、负责人、任务统计和参与项目
- Given 用户点击项目卡片，When 项目详情模态框打开，Then 展示该项目完整信息

### P0-02 部门与智能体管理

> **As a** 未来新员工（或新智能体），
> **I want** 查看每个部门负责人的详细档案，包括能力、故事和负责项目，
> **So that** 我能在 5 分钟内了解公司组织架构和找对人。

**验收标准：**
- Given 用户打开部门页面，When 页面加载完成，Then 每个部门有独立卡片展示负责人头像、故事、能力标签
- Given 用户点击「展开完整故事」，When 按钮被点击，Then 动画展开显示完整故事文本
- Given 用户查看部门卡片底部，When 页面加载完成，Then 显示该部门负责的所有项目及进度

### P0-03 项目看板

> **As a** Wenner（CEO），
> **I want** 查看所有项目列表，按状态筛选，并点击任意项目查看详细进度和任务分配，
> **So that** 我能监控每个项目的里程碑完成情况和资源分配。

**验收标准：**
- Given 用户打开项目页面，When 页面加载完成，Then 显示所有项目卡片，含状态标签、进度条、任务数、截止日期
- Given 用户在搜索框输入关键词，When 输入完成，Then 实时过滤显示匹配的项目
- Given 用户点击项目卡片，When 点击完成，Then 打开项目详情模态框，含三个 Tab：项目看板、周期设置、协作流程
- Given 用户切换模态框 Tab，When 点击 Tab 按钮，Then 内容区域切换对应视图，带入场动画

### P0-04 任务管理

> **As a** Irra（CTO），
> **I want** 在看板视图中看到所有任务按状态分组，高优先级任务醒目，支持筛选项目，
> **So that** 我能快速找到当前需要处理的高优先级任务，并了解任务所属项目。

**验收标准：**
- Given 用户打开任务页面，When 默认看板视图，Then 显示 4 列看板（待处理/进行中/待审核/已完成），每列显示对应任务卡片
- Given 用户点击「列表」按钮，When 切换视图，Then 显示列表形式，含复选框、任务名、项目、优先级、部门、状态、负责人、截止日
- Given 用户选择项目筛选器，When 选择特定项目，Then 只显示该项目的任务
- Given 用户选择优先级筛选器，When 选择「高优先级」，Then 只显示高优先级任务
- Given 用户点击新建任务按钮，When 按钮被点击，Then 弹出任务创建表单（MVP 中可仅展示按钮，表单后续实现）

### P0-05 文档中心

> **As a** Mery（CIO），
> **I want** 在一个地方查看所有设计文档、技术文档和产品文档，按类型快速筛选，
> **So that** 我不需要翻聊天记录找文档链接。

**验收标准：**
- Given 用户打开文档页面，When 页面加载完成，Then 显示所有文档列表，含文档名、类型、部门、更新者、时间、状态
- Given 用户点击文档类型筛选按钮，When 选择「技术文档」，Then 只显示技术文档
- Given 用户在搜索框输入关键词，When 输入完成，Then 实时过滤匹配文档
- Given 用户鼠标悬停在某行文档，When 悬停时，Then 显示「查看」和「下载」操作按钮

## 五、数据指标

### 北极星指标（North Star Metric）

**指标名：** 项目按时完成率
**定义：** 截止日前完成的项目数 / 总项目数
**目标值：** MVP 阶段 ≥ 80%（当前 5 个项目中 1 个已完成，目标在 8 月前达到 80%）
**为什么选这个：** 平台的核心价值是提升项目执行效率，按时完成率直接反映平台对项目管理的实际效果。

### 辅助指标

| 指标 | 定义 | 目标 | 数据来源 |
|------|------|------|---------|
| 任务平均完成周期 | 从创建到完成的平均天数 | ≤ 5 天 | 任务数据中 completedAt - 创建日期 |
| 跨部门项目占比 | 涉及 2 个及以上部门的项目 / 总项目 | ≥ 60% | 项目数据中 involvedDepartments 长度 |
| 文档更新频率 | 每周新增/更新文档数 | ≥ 3 篇/周 | 文档数据中 updatedAt 时间戳 |
| 平台活跃度（DAU） | 每日活跃用户数（智能体） | 4 人/天 | 登录或页面访问日志 |

## 六、非功能需求

### 性能要求

| 指标 | 目标 | 说明 |
|------|------|------|
| 首屏加载时间（FCP） | ≤ 1.5s | 包含 GalaxyCanvas 粒子系统初始化 |
| 页面切换动画 | ≤ 300ms | Framer Motion 动画不卡顿 |
| 搜索响应时间 | ≤ 100ms | 纯前端过滤，无需后端请求 |
| 模态框打开时间 | ≤ 200ms | GSAP 动画入场 |

### 安全要求

- **身份验证：** 所有页面需要登录后才能访问（当前原型未实现，后续接入身份验证）
- **权限控制：** 创始人拥有所有权限；CEO 可查看所有项目但不可修改他人任务；部门负责人只能修改本部门任务
- **数据隔离：** 敏感项目（如技术架构重构）仅对相关人员可见

### 兼容性要求

| 维度 | 要求 |
|------|------|
| 浏览器 | Chrome 90+、Firefox 88+、Safari 14+、Edge 90+ |
| 响应式 | 桌面端优先（1200px+），兼容平板（768px+），移动端侧边栏自动折叠 |
| 深色模式 | 仅支持深色模式，作为品牌视觉的一部分 |

### 可访问性

- 所有颜色对比度符合 WCAG 2.1 AA 标准（深色背景下的文字对比度）
- 键盘导航支持（Tab 键切换、Enter 确认）
- 图标 + 文字标签组合，不依赖纯图标传达信息

### 各页面详细说明

#### 1. 总览页面（Dashboard）

**结构（从上到下）：**

| 区块 | 内容 | 数据来源 |
|------|------|---------|
| Hero 区域 | GalaxyCanvas 粒子背景 + 标题文字（GSAP SplitTextReveal 逐字动画） + 新建项目/任务按钮 | 静态文案 + 跨部门项目计数 |

#### 2. 部门页面（Departments）

**结构：**

| 区块 | 内容 |
|------|------|
| 页面标题 | 「你的智能体团队」+ 描述 |

**交互：**

### 实体详细定义

#### 1. Agent（智能体）

```typescript
interface Agent {
  id: string;              // 唯一标识，如 'irra', 'mery'
  name: string;            // 显示名称
  title: string;           // 完整职位，如 "首席技术官 · 技术部负责人"
  department: string;      // 所属部门名称
  role: string;            // 角色简称，如 'CTO', 'CIO'
  avatar: string;          // 头像路径
  colorTheme: 'blue' | 'gold';  // 视觉主题色
  badge: string;           // 徽章文字
  story: {                 // 个人故事
    summary: string;       // 摘要（2行）

  abilities: string[];     // 能力标签列表

}
```

## 九、附录

### 技术实现约束（Mery 评估）

| 约束项 | 说明 | 影响 |
|--------|------|------|
| 无后端 | 当前为纯前端原型，数据为静态 Mock | P0 功能可完全实现；P1 需后端支持 |
| 无持久化 | 协作流程拖拽调整仅在内存中 | 刷新页面后重置 |
| 无实时通信 | 智能体状态为静态数据 | 无法实时显示在线/离线变化 |
| 无文件系统 | 文档中心无真实上传下载 | 仅展示文件元数据 |
| 粒子系统性能 | GalaxyCanvas 1400 粒子 + 200 星星 | 低端设备可能掉帧，需考虑降级方案 |

### 设计原则回溯

- **MVP 优先：** 首版只实现 P0 五个核心功能，P1 和 P2 留作后续迭代
- **可落地：** 所有设计元素已在前端原型中实现，Irra 只需补充后端即可上线
- **数据驱动：** 所有指标基于现有 Mock 数据计算得出，后端接入后可直接复用
